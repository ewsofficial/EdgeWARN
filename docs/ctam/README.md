# CTAM Framework

CTAM (Convective Threat Analysis Module) is a modular framework for analyzing storm cells and grid-based weather data to detect and assess convective weather threats. It provides a standardized interface for developing and integrating analysis modules that can operate on storm cells or raw raster data.

## Overview

The CTAM framework is designed to:
1. Provide a common interface for analysis modules
2. Support both cell-based and grid-based analysis
3. Enable automatic module discovery and registration
4. Handle module execution and error reporting
5. Manage alert generation and publication
6. Provide history caching for analysis modules

## Framework Structure

```
ctam/
├── __init__.py          # Framework entry point (exports main components)
├── interface.py         # Abstract base classes for modules
├── engine.py            # Module initialization and execution
├── registry.py          # Module registry for discovery and registration
├── run.py               # Main pipeline entry point
├── modules/             # Module implementations
│   ├── __init__.py      # Module exports and registration
│   ├── FLOHAR/          # Flood hazards detection module
│   ├── MorphoWind/      # Morphological wind risk assessment module
│   └── StormCast/       # Storm motion prediction module
└── util/                # Utility functions
    ├── history_cache.py # Cell history cache
    ├── history.py       # History file handling
    └── json.py          # JSON utilities
```

## Core Components

### Module Interfaces

#### AnalysisModule (Cell-based)

```python
class AnalysisModule(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """Unique name of the module."""
        pass
    
    @abstractmethod
    def run(self, storm_entry: Dict[str, Any], environment: Optional[Dict[str, Any]] = None, history_cache: Optional[Any] = None) -> None:
        """Perform analysis on a single storm entry."""
        pass
    
    def alerts(self, storm_entry: Dict[str, Any]) -> Optional[List[AlertPayload]]:
        """Return alert payloads generated by this module."""
        return None
```

#### GridAnalysisModule (Grid-based)

```python
class GridAnalysisModule(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """Unique name of the module."""
        pass
    
    @abstractmethod
    def run(self) -> Dict[str, Any]:
        """Run grid-based analysis on raw data files."""
        pass
    
    def alerts(self, features: List[Dict[str, Any]]) -> Optional[List[AlertPayload]]:
        """Return alert payloads generated by this module."""
        return None
```

#### CellModuleRegistry

```python
class CellModuleRegistry:
    @classmethod
```

## Pipeline Execution

### Main Entry Point

```python
def run_ctam(cells: List[Dict[str, Any]], timestamp: Optional[str] = None) -> List[Dict[str, Any]]:
    """
    Run all registered CTAM modules on the provided storm cells.
    
    First runs cell-based modules, then runs grid-based modules.
    Grid results are attached to the first cell for output.
    
    This is the single entry point for CTAM processing in the pipeline.
    """
```

### Pipeline Steps

1. **Initialization**: Clean up expired alerts
2. **Module Discovery**: Get registered cell and grid modules
3. **Cell-based Analysis**:
   - Initialize cell modules
   - Preload history cache
   - Run each cell-based module
   - Collect and publish alerts
4. **Grid-based Analysis**:
   - Run each grid-based module
   - Collect and publish alerts
5. **Results Attachement**: Attach grid results to first cell
6. **Snapshot Creation**: Create timestamp snapshot of active alerts

## Module Registration

Modules are automatically registered when imported. The registration process happens in two places:

1. Individual module initialization files
2. `modules/__init__.py` which imports all available modules

## Alert Management

The framework uses an `AlertManager` to:
1. Publish alerts from modules
2. Create alert snapshots at specific timestamps
3. Clean up expired alerts
4. Maintain alert history

## History Caching

The `CellHistoryCache` provides:
1. Preloading of active cell history
2. In-memory caching of cell history data
3. Reduction of redundant file reads

## Configuration

Module configuration is typically handled within each module's `config.py` file. Common configuration parameters are defined at the framework level.

## Usage

### Basic Usage

```python
from EdgeWARN.core.ctam.run import run_ctam

# Run all registered modules on storm cells
processed_cells = run_ctam(storm_cells)

# Access module outputs
for cell in processed_cells:
    if 'modules' in cell:
        for module_name, module_data in cell['modules'].items():
            print(f"Module: {module_name}, Data: {module_data}")
```

## Performance Considerations

- Module initialization and execution time is tracked
- History cache reduces redundant file reads
- Modules are executed sequentially but can implement parallel processing internally
- Error handling ensures pipeline continues if individual modules fail

## Extending the Framework

### Creating a New Cell-based Module

```python
from EdgeWARN.core.ctam.interface import AnalysisModule

class MyModule(AnalysisModule):
    @property
    def name(self) -> str:
        return "MyModule"
    
    def run(self, storm_entry: Dict[str, Any], environment: Optional[Dict[str, Any]] = None, history_cache: Optional[Any] = None) -> None:
        # Perform analysis here
        storm_entry["modules"][self.name] = {"result": "analysis_data"}
    
    def alerts(self, storm_entry: Dict[str, Any]) -> Optional[List[AlertPayload]]:
        # Generate alerts here
        return None
```

### Registering a New Module

Add the module to `modules/__init__.py`:

```python
# modules/__init__.py
from .MyModule import MyModule

# Register modules
CellModuleRegistry.register(MyModule())
```
