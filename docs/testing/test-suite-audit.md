# EdgeWARN-Core test-suite audit

Audit date: 2026-09-07. Repository: `ewsofficial/EdgeWARN-Core`. Audited checkout: **`ebc52d693333bb8f80dcc24cd238fc37d65ce40b`**, merge of PR #97, package version 3.0.0.

Scope and evidence: the local checkout's `origin` is the canonical GitHub repository. `git ls-remote origin HEAD` failed because DNS could not resolve the remote, so this report does **not** claim that the checkout is still the latest remote HEAD. All **255 tracked files under `tests/`** are inventoried individually, including fixtures, JSON/TOML data, empty package markers and contributor instructions. Local ignored `__pycache__/*.pyc` files are generated artifacts, not canonical test/support sources; 159 were present after collection. They have no regression value and may be regenerated or removed. The pre-existing deletion of `TODO.md` was left untouched.

This is a static architecture and assertion audit, supported by test-runner probes. AST inspection enumerated every Python source file's test definitions, imports and fixtures; source-body review examined assertions, mocking, control flow and production boundaries. **[E]** denotes directly observed source/configuration or execution evidence; **[I]** denotes an inferred gap or recommended change. No coverage percentage, mutation score, complete Python pass count or meteorological forecast-skill result is claimed.

Companion artifacts:

- [Sortable inventory CSV](test-suite-inventory.csv): the same 255 rows and all 14 requested fields.
- [Per-file evidence index](test-suite-evidence.json): source hashes, line counts, exact test function names/locations, imports, fixtures and patch targets. Imports include mocked boundaries and unused imports; they are **not** a call graph or coverage report.

## 1. Executive Summary

The suite contains substantial protection for runtime correctness, but its organization and labels overstate system-level confidence. Its strongest tests prevent mixed-time inputs, lost durable checkpoints, partially visible files, incorrect storm ancestry, orphan processes and invalid API access. Its weakest area is the connected weather-data path: authentic input decoding through detection, enrichment, forecasting, publication and API consumption is not established by the nominal integration directory.

**[E]** The canonical tree has 135 `test_*.py` files, six JavaScript test files, 14 `benchmark_*.py` files, one telemetry-analysis script, 44 JSON baselines, two TOML manifests, two fixture entrypoints, two conftests, two snapshot helpers, one source-inspection helper, 21 empty `__init__.py` files and 25 `AGENTS.md` files. Static enumeration found 1,676 Python `test_*` function definitions, including the explicitly invoked RAP benchmark. This is not the number of collected parametrized cases.

The largest sources of avoidable maintenance are:

1. **Configuration migration characterization duplicated across several layers.** Effective-value snapshots, literal lengths, catalog invariants, AST signatures and source substring checks often enforce overlapping facts. Some alternate-value configuration tests are excellent and must survive consolidation.
2. **Integration claims without connected production work.** `test_full_detect_to_integrate_pipeline` constructs and edits a dictionary entirely inside the test. The ingest-to-detect file replaces the data handler, mapper and saver. These cannot establish the advertised boundary.
3. **Scattered issue-based regressions.** `test_critical_fixes.py`, `test_high_fixes.py`, `test_medium_audit_fixes.py`, `test_low_audit_fixes.py` and `test_runtime_correctness_reproductions.py` mix ownership. Most underlying regressions are worth keeping; the file taxonomy is not.
4. **Performance harness duplication and unreliable defaults.** Seven NEXRAD-specific benchmark scripts overlap in discovery, process creation, sampling or export setup. Default pytest also discovers hardware/data-dependent performance checks.
5. **Weak or dormant protection.** Some geometry/tracking tests assert only type or count, three retired serializer tests are permanently skipped, and four JSON snapshots have no current consumer.

**Execution evidence:** `npm test -- --runInBand` passed **6 suites / 54 tests** after running with local socket binding available. The initial sandboxed run failed in Supertest with `listen EPERM`; those failures are environmental, not demonstrated API regressions. Python collection in the activated `EdgeWARN-dev` environment stopped with **64 errors and 1,088 partially collected cases** because native dependencies loaded by rasterio, netCDF4 and pyproj reported `undefined symbol: BrotliSharedDictionaryDestroyInstance`. The dependency environment was not changed. This local result does not establish that canonical CI is failing.

**[I]** Keep the failure-state and boundary tests. Reduce declaration-level duplication and replace misleading happy-path smoke tests with a few deterministic, connected weather-data slices. Test count should fall only where the removed cases fail to exclude a distinct realistic regression.

## 2. Test Suite Architecture

### Current directory responsibilities

| Location | Actual role | Important limitation |
| --- | --- | --- |
| `tests/core/` | Most Python module, component, configuration and CTAM tests; includes real file I/O, local HTTP and subprocess work | Not synonymous with isolated unit tests; EWMRS rendering lives under `ingest/` |
| `tests/unit/` | Tracking algorithms, issue-based regressions, CLI/package work and process supervision | Contains real process trees and cross-component failure tests |
| `tests/integration/` | A mixture of genuine boundary slices, mocked orchestration and mislabeled smoke tests | Directory placement does not establish integration scope |
| `tests/util/` | File/logging helpers plus critical runtime coordination, records, heartbeats and consumers | “Utilities” hides service orchestration and restart behavior |
| `tests/api/` | Six Jest files for the unified `src/api/` service and `src/config/loader.js` | Empty `routes/`, `utils/` and `performance/` scaffolding suggests organization that does not exist |
| `tests/benchmarks/` | Synthetic experiments, real-data timing checks, live service memory profilers and telemetry parsing | Two files match default pytest discovery; most others require explicit invocation |
| `tests/config_baseline/` | 31 normalized configuration/source-surface snapshots | Some freeze declaration shape rather than operator-visible behavior; one appears orphaned |
| `tests/ctam_baseline/` | 13 forecast/history/schema-shape snapshots | Three stormcell-shape snapshots appear orphaned |
| `tests/fixtures/ctam_modules/` | Valid and deliberately invalid external-module installations | Entrypoint placeholders are inert; discovery does not execute them |

### Pytest and shared state

**[E]** [pytest.ini](../../pytest.ini) sets `pythonpath = src`, `testpaths = tests`, `python_files = test_*.py`, asyncio auto mode, verbose short tracebacks, strict markers and `--ignore=tests/api`. It globally suppresses deprecation and pending-deprecation warnings. Coverage is only suggested in commented configuration.

The registered classification markers are `unit`, `integration`, `e2e`, `slow`, `api`, `ingest`, `process` and `ctam`. AST inspection found use of `asyncio`, `parametrize`, `ctam`, skip/skipif and unused xfail marker constructors, but **no application of the registered unit/integration/e2e/slow/api/ingest/process categories**. Thus `-m 'not slow'` does not reliably exclude expensive work. Pytest's `asyncio` marker comes from the plugin; it need not appear in the custom marker list.

[tests/conftest.py](../../tests/conftest.py) adds `src` to `sys.path` again, supplies a logger mock and a small temporary directory layout, and uses an autouse fixture to set `EDGEWARN_ENV=test` and register restoration of `EDGEWARN_CONFIG_DIR`. The config root may still inherit the invoking shell's value. `mock_fs` creates directories but **does not redirect every `util.file` path**. Several tests call `fs.initialize_filesystem()` or change global caches themselves. There is no root-level restoration of the entire runtime filesystem/configuration state.

The localized [integration configuration fixture](../../tests/core/process/integrate/conftest.py) is particularly good: it copies the configuration tree, changes a setting away from the shipped value, and resets loader/integrator caches. Tests such as `test_output_decimals_is_live_at_both_integrator_sites` prove that configuration changes reach execution, rather than comparing two copies of the same default.

Shared builders are mostly local. Logging fixtures are repeatedly recreated. More significantly, tests import support from other **test modules**, such as the pointer `TABLE` in `test_pointer_allowlist.py`. Move genuinely shared inputs to fixture/helper modules; avoid a giant root conftest that imports every scientific dependency.

### Jest and CI

**[E]** [jest.config.js](../../jest.config.js) uses Node, native ES modules with no transform, a 10-second test timeout, cleared/restored mocks and three filename patterns under `tests/api/`. Its coverage collection paths correctly point at `src/api/**/*.js` and `src/config/loader.js`. Configured global thresholds are 66% branches, 78% functions, 89% lines and 70% statements, but **coverage collection is not enabled by default**. [package.json](../../package.json) exposes a separate `test:coverage` command.

[.github/workflows/ci.yml](../../.github/workflows/ci.yml) contains:

- `node-tests`: Ubuntu, Node 20, `npm ci`, configuration validation, then `npm test` without coverage.
- `python-tests`: Ubuntu, Python 3.13 via the `EdgeWARN-dev` Conda environment, configuration validation, then default pytest with `faulthandler_timeout=120` and a 25-minute step timeout.
- `package-command`: builds and installs a wheel, smoke-tests help/version/configuration outside the checkout, then runs installed-command/package-run/launcher tests.

`faulthandler_timeout` prints diagnostics; it is **not a per-test termination deadline**. No Python coverage command/report, default benchmark exclusion, network-off policy, test result upload or Windows/macOS job is present in this workflow. The suite contains useful Linux/POSIX signal tests, but passing them says nothing about other operating systems.

The package job adds genuine delivery confidence. It also repeats tests included in the default Python run. The installed-command fixture builds another wheel in its own venv, so the current workflow can build wheels three times: once in the main Python suite, once in the explicit package build, and again in the package pytest fixture. Share the built artifact or select a dedicated packaging lane while preserving the outside-checkout test.

## 3. Complete Test Inventory

The following tables contain **one row for each tracked file**. Paths are relative to the repository root and link to the source. The [CSV](test-suite-inventory.csv) is easier to filter than the wide Markdown tables.

Interpretation:

- **Category and scope describe actual test behavior**, not just its directory. “End-to-end” would require the relevant production entrypoint and real internal boundaries; no ordinary test here establishes the complete ingest-to-HTTP system.
- **Regression value:** Critical = prevents broken operational availability, data integrity, access boundaries or core tracking/coordination; High = distinct important behavior; Medium = useful but narrow/weakly asserted; Low = little demonstrated runtime protection. Support files inherit value only through their consumers.
- **Maintenance burden:** expected cost of keeping fixtures, duplicated contracts and setup aligned. **Brittleness risk:** likelihood of failure from timing/platform/source-layout changes unrelated to the intended contract. Both are qualitative judgments, not measurements.
- File-level ratings represent the important retained cases, not every assertion. A Critical file may contain deletable smoke tests.
- “Important functions/classes/modules” names key referenced production surfaces; the mocks column identifies replaced boundaries. Imports alone do not prove execution. The evidence index lists the complete extracted definitions/imports for review.
- “Filesystem” normally means temporary synthetic artifacts or checked-in documents, **not real weather data**. Explicit real-data/live benchmark dependencies are called out. All default Python tests also inherit the root environment fixture and may import a larger scientific stack than their immediate algorithm needs. No external trained-ML inference is established by these tests; RAP is weather-model input.
- Keep/Move/Merge are recommendations, not changes performed by this audit. A move/merge must retain every distinct behavioral contract unless deletion is explicitly justified. Overlap paths abbreviated within a component refer to the neighboring inventory entries.

## 7. Structural Problems

1. **Classification is nominal.** `core`, `unit` and `util` all contain overlapping component work; `integration` includes isolated fakes, while CTAM HTTP/process tests live under `core`. The registered scope/speed markers do not currently select these groups.
2. **Naming records migration history rather than ownership.** “Phase 0/3/7,” severity-based fix filenames and stale docstrings survive completed changes. The runtime reproduction file defines three xfail marker objects but does not apply them to its tests. It should no longer describe the active regressions as expected failures.
3. **Fixtures can mask meaningful work.** The saver tests install an autouse synthetic morphology module. That is reasonable for saver isolation, but architecture documentation must not credit those tests with morphology coverage. `mock_datasets` in RAP integration is unused. Repeated local logger fixtures and per-file mock graphs should be simplified selectively.
4. **Shared source inspection is too entangled with correctness.** `test_known_drift.py` mixes valuable altered-config execution with exact text/default/signature checks. `test_doc_citations.py` enforces citation count and line bounds, which cannot verify citation meaning. Keep them in separate architecture/docs lanes.
5. **Import topology couples unrelated tests to native libraries.** The same native Brotli symbol failure blocked 64 test modules (50 via rasterio, 12 via netCDF4 and two via pyproj). `EdgeWARN/__init__.py` imports pipeline exports; even narrow imports can pull in broad scientific dependencies. This is evidence to investigate lazy package exports and lighter fixtures, not evidence that those 64 behaviors are broken.
6. **Timing assertions and sleeps create avoidable brittleness.** Both lineage performance cases assert under 500ms in default integration; CTAM performance thresholds are default-discovered; launcher tests sleep for startup and some async coordinator tests use milliseconds to impose order. Use events/readiness handshakes for correctness and calibrated repeated measurements for performance.
7. **Environment-sensitive work is not explicitly gated.** Performance fixtures search the runtime base directory and can skip on one machine yet execute real analysis on another. This changes both coverage and side effects. Require explicit benchmark dataset/output arguments.
8. **CI thresholds are mostly aspirational.** Jest thresholds are configured but default CI does not collect coverage; Python does not request it. No complete coverage result is available from this audit. Introduce reports before choosing policy thresholds and ensure process work is included in the coverage method.
9. **Package checks duplicate expensive setup.** Dedicated packaging is justified; rebuilding/reinstalling inside multiple jobs adds little if the same delivery contract is exercised repeatedly. Select packaging tests once against the produced wheel.
10. **Repository scaffolding is stale.** Empty Python package markers in the Jest tree have no function; empty API directory guidance should move with real JS tests or be removed. Conversely, removing every Python `__init__.py` blindly can cause duplicate-basename import conflicts or break imports between test helpers.

## 10. Documentation-Ready Summary

EdgeWARN-Core uses pytest for Python processing, configuration, persistence and runtime orchestration, and Jest/Supertest for the unified Node API. Python tests use synthetic arrays, temporary artifacts and mocked remote transports to validate detection, tracking, enrichment and failure handling. Higher-level tests exercise durable readiness records, consumer checkpoints, publication recovery, CTAM HTTP/subprocess boundaries and service shutdown. An installed-wheel test runs outside the source checkout to validate package delivery.

The strongest regression contracts concern scan-time consistency, storm identity, atomic artifact publication, replay/retry state and API access/serialization. Golden fixtures preserve selected configuration and StormCast/history behavior. Live-data and hardware-sensitive scripts provide performance measurements and should be run explicitly with controlled inputs. The current suite still mixes execution scopes across directories and includes misleading smoke tests; it should not be described as complete end-to-end weather-pipeline coverage.
